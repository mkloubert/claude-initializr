Веб-застосунок для генерації конфігураційних файлів Docker для безпечного запуску [Claude Code](https://docs.anthropic.com/en/docs/claude-code) в контейнеризованому середовищі.

**Демо:** [https://claude.kloubert.dev](https://claude.kloubert.dev)

## Функції

### Конфігурація Dockerfile

- **Базовий образ**: Налаштування назви та версії базового Docker образу (за замовчуванням: `node:24`)
- **Вибір програмного забезпечення**: Виберіть додаткове ПЗ для встановлення:
  - ffmpeg (обробка аудіо/відео)
  - Flutter (включає Dart та Android SDK)
  - Go
  - ImageMagick (обробка зображень)
  - Python 3
  - Rust (включає менеджер пакетів Cargo)
  - TypeScript
  - uv (швидкий інсталятор пакетів Python, рекомендує Python)
  - Ollama (підключення до локального екземпляра Ollama для використання моделей з відкритим кодом)
- **Налаштування версій**: Версії програмного забезпечення налаштовуються через аргументи збірки Docker (напр. `--build-arg GO_VERSION=1.22.0`)
- **Користувацькі пакети APT**: Додайте додаткові пакети Debian/Ubuntu для встановлення в контейнер
- **Користувацькі пакети NPM**: Додайте додаткові NPM пакети для глобального встановлення з можливістю встановлення від імені користувача `root` або `node`
- **Користувацькі команди RUN**: Додайте користувацькі shell-команди для виконання під час збірки Docker-образу з можливістю виконання від імені користувача `root` або `node`

### Конфігурація docker-compose.yaml

- **Змінні середовища**: Налаштуйте змінні середовища для вашого файлу `.env`
- **Захищені файли**: Вкажіть файли, які потрібно захистити шляхом монтування порожніх файлів тільки для читання (запобігає доступу до чутливих файлів, таких як `.env.local`)

### Редактор CLAUDE.md

- Markdown редактор з підсвічуванням синтаксису
- Вбудована функція попереднього перегляду
- Написання проектних інструкцій для Claude

### Конфігурація settings.json

- **Правила дозволів**: Налаштуйте дозволи Claude Code для керування доступом до файлів
  - `Allow` - Правила для автоматично дозволених операцій
  - `Ask` - Правила, що вимагають підтвердження користувача
  - `Deny` - Правила, які завжди відхиляються
- **Підтримувані директиви**:
  - `Read()` - Визначає, які файли Claude може читати (напр: `Read(src/**)`)
  - `Edit()` - Визначає, які файли Claude може редагувати (напр: `Edit(.env)`)
  - `WebFetch()` - Контролює мережевий доступ (напр: `WebFetch(https://api.github.com:*)`)
- **Автоматична інтеграція**: Захищені файли автоматично додаються як правила заборони `Read()`
- **Підтримка Glob-шаблонів**: Використовуйте шаблони на кшталт `src/**` для рекурсивного співставлення

### Конфігурація DevContainer (VS Code / GitHub Codespaces)

- **Інтеграція з VS Code**: Генеруйте `devcontainer.json` для VS Code Dev Containers
- **GitHub Codespaces**: Сумісна конфігурація для розробки в GitHub Codespaces
- **Розширення**: Налаштуйте розширення VS Code для автоматичного встановлення
- **Налаштування**: Визначте налаштування VS Code для середовища контейнера
- **Features**: Додайте Dev Container Features (напр: GitHub CLI, додаткові мови)
- **Переадресація портів**: Налаштуйте порти для переадресації з контейнера
- **Команди життєвого циклу**: Налаштуйте команди для подій post-create, post-start та post-attach
- **Рекомендовані розширення**: Автоматичні рекомендації розширень на основі вибраного програмного забезпечення

### Механізм автозбереження

Функцію автозбереження можна перемикати за допомогою іконки збереження в заголовку:

| Іконка           | Стан        | Поведінка                                                         |
| ---------------- | ----------- | ----------------------------------------------------------------- |
| 💾 (Зберегти)    | Увімкнено   | Всі зміни автоматично зберігаються в localStorage                 |
| 🚫💾 (Вимкнено)  | Вимкнено    | Зміни не зберігаються; існуючі збережені дані видаляються         |

**Як це працює:**

- **Увімкнення автозбереження**: Негайно зберігає поточні налаштування в localStorage
- **Вимкнення автозбереження**: Видаляє всі збережені налаштування з localStorage
- Ваші налаштування автозбереження запам'ятовуються між сесіями

### Імпорт/Експорт конфігурації

Ви можете ділитися або створювати резервні копії конфігурації через JSON-файли:

- **Експорт**: Натисніть на іконку завантаження в заголовку, щоб завантажити поточну конфігурацію як `claude-initializr-config.json`
- **Імпорт**: Натисніть на іконку скачування, щоб вибрати раніше експортований JSON-файл

**Як це працює:**

- **Експорт** зберігає всі налаштування (базовий образ, вибір програмного забезпечення, пакети, команди, дозволи, вміст CLAUDE.md) в один JSON-файл
- **Імпорт** перевіряє файл, показує попередній перегляд змін і запитує підтвердження перед застосуванням
- З міркувань безпеки **значення змінних оточення ніколи не включаються** до експортованих файлів — експортуються лише назви змінних
- Імпортовані конфігурації отримують нові внутрішні ідентифікатори для запобігання конфліктам
- Формат експорту включає поле версії (`"version": "1.0"`) для прямої сумісності

### Конфіденційність та зберігання даних

Цей застосунок поважає вашу конфіденційність:

- **Лише локальне сховище**: Всі налаштування зберігаються локально у вашому браузері (localStorage)
- **Без зв'язку з сервером**: Жодні дані ніколи не відправляються на сервер
- **Безпека за проектом**: **Значення** змінних середовища **ніколи не зберігаються** - зберігаються лише імена змінних
- **Повний контроль**: Ви можете вимкнути автозбереження будь-коли за допомогою перемикача в заголовку, що також видаляє всі збережені дані
- **Тема на основі сесії**: Налаштування теми скидаються до системних за замовчуванням при перезавантаженні сторінки

## Функції безпеки

Згенерована конфігурація Docker містить комплексні заходи безпеки:

### Мережевий брандмауер

Скрипт `init-firewall.sh` реалізує строгу мережеву ізоляцію:

- **Брандмауер на основі iptables** з політикою DROP для всього вихідного трафіку
- **Підхід лише білого списку** - доступні лише схвалені домени:
  - `api.anthropic.com` - Claude API
  - `npm registry` - Встановлення пакетів
  - `github.com` - Git операції
  - `sentry.io` - Звітування про помилки
- **Автоматичне визначення IP GitHub** для web, API та git кінцевих точок
- **Ізоляція хост-мережі** - запобігає доступу до локальної мережі
- **Перевірка брандмауера** - тести гарантують правильне застосування правил

### Посилення безпеки Docker

- **Видалення можливостей**: Всі Linux можливості видаляються (`cap_drop: ALL`)
- **Без підвищення привілеїв**: `no-new-privileges:true`
- **Обмеження ресурсів**: Обмеження CPU та пам'яті
- **Монтування лише для читання**: Захищені файли монтуються лише для читання
- **Виконання без root**: Виконується від імені користувача `node`

## Використання

1. **Налаштуйте базовий образ**: Встановіть назву та версію базового Docker образу (наприклад, `node:24` або `node:22-slim`)

2. **Виберіть програмне забезпечення**: Виберіть додаткове ПЗ для встановлення в контейнер

3. **Додайте користувацькі пакети та команди**:
   - Додайте користувацькі APT пакети (наприклад, `curl`, `graphviz`, `sqlite3`)
   - Додайте користувацькі NPM пакети для глобального встановлення (наприклад, `eslint`, `prettier`)
   - Виберіть, чи мають NPM пакети встановлюватися від імені користувача `node` (за замовчуванням) чи `root`
   - Додайте користувацькі команди RUN для виконання під час збірки (наприклад, `pip install numpy`)
   - Виберіть, чи мають команди RUN виконуватися від імені користувача `node` (за замовчуванням) чи `root`

4. **Встановіть змінні середовища**: Додайте змінні середовища, необхідні вашому проекту (наприклад, `ANTHROPIC_API_KEY`)

5. **Захистіть чутливі файли**: Додайте шляхи до файлів, які потрібно захистити (наприклад, `.env.local`)

6. **Редагуйте CLAUDE.md**: Напишіть інструкції для Claude в Markdown редакторі

7. **Налаштуйте дозволи**: Встановіть правила дозволів через розділ settings.json
   - Додайте правила `Allow` для автоматично схвалених операцій
   - Додайте правила `Ask` для операцій, що вимагають підтвердження
   - Додайте правила `Deny` для заборонених операцій
   - Захищені файли автоматично додаються як правила заборони `Read()`

8. **Попередній перегляд**: Перевірте згенеровані конфігураційні файли у панелі живого попереднього перегляду

9. **Завантажте**: Натисніть "Завантажити ZIP" щоб отримати всі файли

## Використання згенерованих файлів

1. Розпакуйте ZIP файл у директорію вашого проекту

2. Скопіюйте файли проекту в папку `workspace` (або змонтуйте існуючий проект)

3. Встановіть ваш API ключ у файлі `.env`:

   ```bash
   ANTHROPIC_API_KEY=ваш-api-ключ-тут
   ```

4. Зберіть та запустіть контейнер:

   ```bash
   docker compose up --build
   ```

   **Опціонально: Користувацькі версії програмного забезпечення**

   Ви можете налаштувати версії програмного забезпечення під час збірки Docker за допомогою аргументів збірки:

   ```bash
   docker compose build \
     --build-arg CLAUDE_CODE_VERSION=1.0.3 \
     --build-arg FLUTTER_VERSION=3.29.3 \
     --build-arg GIT_DELTA_VERSION=0.18.2 \
     --build-arg GO_VERSION=1.24.3 \
     --build-arg PYTHON_VERSION=3.13.2 \
     --build-arg TYPESCRIPT_VERSION=5.8.3 \
     --build-arg ZSH_IN_DOCKER_VERSION=1.2.0
   ```

   | Аргумент збірки | За замовчуванням | Опис |
   |-----------------|------------------|------|
   | `CLAUDE_CODE_VERSION` | `stable` | Версія Claude Code (`latest` або конкретна як `1.0.58`) |
   | `FLUTTER_VERSION` | `latest` | Версія Flutter SDK |
   | `GIT_DELTA_VERSION` | `0.18.2` | Версія git-delta |
   | `GO_VERSION` | `latest` | Версія Go |
   | `PYTHON_VERSION` | `latest` | Версія Python 3 |
   | `TYPESCRIPT_VERSION` | `latest` | Версія TypeScript |
   | `ZSH_IN_DOCKER_VERSION` | `1.2.0` | Версія zsh-in-docker |

   **Опціонально: Користувацькі URL-адреси завантаження**

   Якщо вам потрібно використовувати дзеркало або проксі для завантаження пакетів, ви можете перевизначити URL-адреси за замовчуванням під час збірки. Всі URL-адреси підтримують параметри запиту:

   ```bash
   docker compose build \
     --build-arg GO_JSON_URL=https://my-mirror.example.com/golang/?mode=json \
     --build-arg GO_DOWNLOAD_URL=https://my-mirror.example.com/golang \
     --build-arg RUSTUP_INSTALL_URL=https://my-mirror.example.com/rustup/rustup-init.sh \
     --build-arg FLUTTER_JSON_URL=https://my-mirror.example.com/flutter/releases_linux.json \
     --build-arg FLUTTER_BASE_URL=https://my-mirror.example.com/flutter/releases \
     --build-arg UV_INSTALL_SCRIPT_URL=https://my-mirror.example.com/uv/install.sh
   ```

   | Аргумент збірки | За замовчуванням | Опис |
   |-----------------|------------------|------|
   | `GO_JSON_URL` | `https://go.dev/dl/?mode=json` | URL JSON API версій Go (тільки для "latest") |
   | `GO_DOWNLOAD_URL` | `https://go.dev/dl` | Базова URL для завантаження архівів Go |
   | `RUSTUP_INSTALL_URL` | `https://sh.rustup.rs` | URL скрипта встановлення rustup |
   | `FLUTTER_JSON_URL` | `https://storage.googleapis.com/flutter_infra_release/releases/releases_linux.json` | URL JSON API релізів Flutter (тільки для "latest") |
   | `FLUTTER_BASE_URL` | `https://storage.googleapis.com/flutter_infra_release/releases` | Базова URL для завантаження архівів Flutter |
   | `UV_INSTALL_SCRIPT_URL` | `https://astral.sh/uv/install.sh` | URL скрипта встановлення uv |

5. Підключіться до контейнера:

   ```bash
   docker compose exec claude zsh
   ```

6. Ініціалізуйте брандмауер (потрібен пароль sudo):

   ```bash
   sudo /usr/local/bin/init-firewall.sh
   ```

7. Запустіть Claude Code:
   ```bash
   claude
   ```

## Вирішення проблем

### Проблеми з брандмауером

Якщо виникають мережеві проблеми після увімкнення брандмауера:

```bash
# Перевірте стан брандмауера
sudo iptables -L -n

# Перегляньте заблоковані з'єднання
sudo iptables -L -n -v | grep DROP

# Скиньте брандмауер (дозволяє весь трафік)
sudo iptables -F
```

### Контейнер не запускається

```bash
# Перевірте логи
docker compose logs

# Перезберіть без кешу
docker compose build --no-cache
```

### Відмовлено в доступі

Переконайтеся, що директорія workspace має правильні дозволи:

```bash
chmod -R 755 workspace
```

### Скидання налаштувань застосунку

Щоб очистити всі збережені налаштування та почати заново, відкрийте консоль розробника браузера та виконайте:

```javascript
localStorage.removeItem("claude-initializr-config");
localStorage.removeItem("claude-initializr-welcome-dismissed");
localStorage.removeItem("claude-initializr-autosave");
```

Потім перезавантажте сторінку.

Альтернативно, ви можете вимкнути автозбереження за допомогою перемикача в заголовку, щоб запобігти збереженню налаштувань.

## Релізи

Релізи автоматизовані через GitHub Actions. Щоб створити новий реліз:

1. Створіть і відправте тег версії:
   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```

2. Робочий процес автоматично:
   - Збирає проект
   - Створює ZIP-архів з папки `dist/`
   - Публікує GitHub Release з автоматично згенерованими примітками до випуску

Теги, що містять `-` (напр. `v1.0.0-beta`), позначаються як попередні релізи.
